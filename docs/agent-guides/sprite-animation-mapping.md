# 스프라이트·애니메이션 매핑 지침

## 적용 범위

유닛 방향, 행동 프레임, 건물 건설·피해 상태, 레이어 애니메이션, 브리핑 초상화를 조사하거나
구현할 때 이 문서를 적용한다.

## 현재 기준선

- 현행 매핑 감사: [`analysis/generated/sprite-mapping-audit.json`](../../analysis/generated/sprite-mapping-audit.json)
- 사람이 작성한 판정: [스프라이트 매핑 감사](../reverse-engineering/sprite-mapping-audit.md)
- 원본 분석 방법: [정적 분석 방법론](../reverse-engineering/methodology.md)
- 상태 승격 조건: [증거 및 상태 기준](../reverse-engineering/evidence-levels.md)

감사 보고서에서 `unverified`인 매핑은 파일 경로와 프레임 존재만 확인된 것이다. 방향, 행동, 체력 상태,
인물 정체가 확인됐다는 뜻이 아니며 원작 일치 근거로 사용할 수 없다.

## 필수 규칙

1. 원본 `SPR`과 EXE의 SHA-256을 기록한다.
2. 자원 경로 또는 스프라이트 테이블의 원본 데이터 주소를 찾는다.
3. 상태 값과 방향 값이 프레임 번호로 변환되는 전체 데이터 흐름을 확인한다.
4. 점프 테이블, 범위 검사, 기본 분기, 미러링 여부를 포함한다.
5. 프레임 번호만 맞추지 말고 그 프레임을 선택하는 규칙을 복원한다.
6. 정적 근거와 독립 테스트 벡터를 만든 뒤 현행 테마 매핑을 바꾼다.
7. 근거가 불충분하면 기존 값을 유지하더라도 상태는 `미확인` 또는 `추정`으로 둔다.

다음은 근거로 인정하지 않는다.

- 프레임 이미지를 눈으로 보고 방향이나 행동을 추측
- 연속 프레임의 앞부분을 건설, 뒷부분을 완성·피해 상태라고 가정
- 캐릭터 ID의 숫자를 특정 초상화 자원의 프레임 번호로 직접 변환
- 현재 구현에서 자연스럽게 보인다는 이유로 매핑을 확정
- 파일이 존재하고 렌더링된다는 테스트

## 유닛 방향·행동

다음을 각각 별도 주장으로 검증한다.

- 원본 엔티티 종류 → `SPR` 자원
- 행동·상태 값 → 애니메이션 블록
- 방향 값 → 방향 블록
- 블록 안 프레임 수와 반복·종료 규칙
- 좌우 미러링을 원본이 실제로 수행하는지 여부
- 공격 판정 시점과 표시 프레임의 연결

8방향 배열이나 5방향+미러 배열을 공통 규칙으로 먼저 가정하지 않는다. 유닛마다 테이블이나 상태 수가
다를 수 있다.

현재 [내부 클래스 2 애니메이션 파일럿](../reverse-engineering/mechanics/unit-animation-pilot.md)은
원본 이름 `조선 창병`, 슬롯 100, `swordk.spr`와 상태 1·2의 제한된 방향·미러 식을 정적 확정했다.
상태 1 표는 flags `0x80000008`이 없는 일반 분기에만 적용한다. 원본 이름을 프로젝트 표시 문자열에
반영할 수 있지만, 행동 의미가 연결되기 전에는 상태 1·2를 임의로 `move`·`attack`으로 번역하지 않는다.

## 건물

건설 진행도, 완성 상태, 체력 단계와 장식 레이어를 분리해 추적한다. 특히 완성 프레임과 반파 프레임은
다음 경로가 확인되기 전까지 구분됐다고 주장하지 않는다.

- 건물 렌더 함수가 읽는 필드
- 현재 체력·최대 체력 또는 건설 진행도 계산
- 상태별 분기 경계
- 기본 본체 프레임과 별도 오버레이 선택

현재 [조선 본영 파일럿](../reverse-engineering/mechanics/building-state-pilot.md)은 클래스 49의
건설 프레임 0~7, 정상 프레임 7, 반파 프레임 8과 엄격한 50% 미만 경계를 정적 확정했다. 이 규칙은
`korean-hq`에만 적용하며 다른 건물이나 `hqk.spr` 프레임 9~19로 일반화하지 않는다.

## 브리핑 초상화

`[SPEECH][K3]...` 같은 스크립트 토큰은 인물 ID일 뿐 프레임 번호가 아니다. 다음을 정적으로 복원한다.

1. `SPEECH` 명령 파서와 인수 저장 형식
2. ID 문자열의 조회 테이블과 순서
3. 초상화 자원 선택과 로드 경로
4. 조회 인덱스에서 자원 프레임으로 가는 계산
5. 잘못된 ID와 범위 밖 값의 처리

현재 원본의 `SPEECH` 경로는
[브리핑 초상화 매핑](../reverse-engineering/mechanics/briefing-portraits.md)에서 `hero.spr` 기반으로
정적 확정했다. 이후 변경은 그 추출기와 테스트를 함께 유지해야 한다.

## 변경 통과 조건

매핑 변경은 최소한 다음을 함께 제출해야 한다.

- 원본 파일·해시
- 함수·데이터 주소와 관련 점프 테이블
- 입력 상태·방향·ID와 출력 프레임의 테스트 벡터
- 감사 보고서에서 해당 항목의 상태 승격
- 매핑 테스트와 자원 존재 테스트

동적 확인이 정말 필요하면 [동적 검증 예외 지침](dynamic-validation.md)을 먼저 적용한다. 게임을 직접
플레이하며 화면을 따라가는 방식은 이 작업의 기본 경로가 아니다.
