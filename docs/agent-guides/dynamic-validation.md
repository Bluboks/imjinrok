# 동적 검증 예외 지침

동적 분석은 정적 분석을 대체하지 않는다. 다음 조건을 모두 만족할 때만 제안하거나 수행한다.

## 진입 조건

- 관련 함수의 전체 제어 흐름을 정적으로 분석했다.
- 구조체, 전역과 테이블 참조를 확인했다.
- 결과에 영향을 주는 두 가지 이상의 해석이 남았다.
- 원본 함수 격리 실행이나 정적 테스트로 답을 얻을 수 없다.
- 확인할 질문을 한 문장으로 적을 수 있다.
- 캡처할 함수·주소·필드와 예상 가능한 결과를 미리 문서화했다.

## 허용되는 방식

- 저장 상태 또는 재현 가능한 프로세스 상태에서 시작
- 이벤트 이전에 브레이크포인트나 watchpoint 설치
- 함수 하나, 분기 하나 또는 필드 하나만 캡처
- 레지스터·스택·관련 메모리와 원본 코드 바이트 저장
- 결과를 원본 파일 해시와 함께 저장
- 종료 후 정적 분석 문서의 미확인 항목 하나만 갱신

## 금지되는 방식

- 게임을 플레이하면서 빠르게 변하는 화면을 따라가기
- 클릭 후 일어난 여러 결과를 하나의 원인으로 추정
- 시각적 결과만 기록하고 입력 메모리 상태를 저장하지 않기
- `no-hit`을 코드 경로가 없다는 증거로 일반화
- 패치된 조건의 결과를 자연 실행 전체의 증거로 일반화
- VM 안에만 원시 증거를 남기기

## VM/QGA 안전 규칙

VM이 정말 필요한 경우:

- `/home/bluboks/.local/bin/win10-qga`만 직접 사용한다.
- raw `virsh`, raw QGA, shell wrapper, pipe와 redirect를 사용하지 않는다.
- 이 작업에서 실행한 프로세스에 고유 marker를 붙인다.
- 다른 작업이나 에이전트의 프로세스를 정리하지 않는다.
- 실행한 프로세스만 marker로 명시적으로 정리한다.
- PowerShell 분석 스크립트는 프로세스 범위 실행 정책 우회를 명시한다.

## 결과 상태

동적 캡처는 별도의 보조 증거다. 성공한 캡처가 있어도
[증거 기준](../reverse-engineering/evidence-levels.md)의 `정적 확정`이나 `재현 완료`로 자동 승격되지
않는다.
