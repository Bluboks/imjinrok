# 정적 분석 방법론

## 목적

원본 게임의 동작을 화면 관찰이나 현재 구현에서 추정하지 않고, 바이너리와 데이터의 제어 흐름,
자료구조, 테이블과 수식으로 복원한다.

## 기본 규칙

1. 원본 파일 해시를 확인한다.
2. 분석할 질문을 한 문장으로 제한한다.
3. 문자열·임포트·데이터 참조는 진입점으로만 사용한다.
4. 관련 함수의 전체 분기와 호출 관계를 확인한다.
5. 읽고 쓰는 구조체 필드와 전역 상태를 복원한다.
6. 수식·상수·이벤트 순서를 명시한다.
7. 반대 조건과 실패 경로를 포함한다.
8. 독립 입력·출력 테스트로 재현한다.
9. 재현이 끝난 뒤에만 현재 구현과 비교한다.

## 분석 단위

“전투 시스템 전체”처럼 넓은 목표를 한 번에 분석하지 않는다. 다음처럼 관찰 가능한 질문으로 나눈다.

- 완성된 K01 봉화대는 어떤 조건에서 K0120을 한 번 실행하는가?
- 사거리 경계에서 공격자는 이동 상태와 공격 상태 중 어느 쪽으로 전이하는가?
- 피해 계산은 어떤 정수 순서와 나눗셈 규칙을 사용하는가?
- 애니메이션 프레임 필드는 어느 상태 전이 함수에서 갱신되는가?
- 건물 체력 구간은 어떤 본체·오버레이 프레임을 선택하는가?
- `SPEECH`의 `K10`은 어떤 초상화 자원의 어느 프레임으로 변환되는가?

## 정적 분석 절차

### 1. 입력 고정

- [바이너리 기준 정보](binary-manifest.md)의 SHA-256을 확인한다.
- 패치된 실행 파일이나 VM 작업 복사본을 원본 정적 근거로 사용하지 않는다.
- 원본 자원 파일이 필요한 경우 경로와 해시를 별도로 기록한다.

### 2. 진입점 탐색

다음을 이용해 후보를 찾는다.

- 문자열과 파일명 참조
- 임포트 호출
- 전역 테이블 참조
- 이미 확인된 호출자·피호출자
- 진단 문자열과 소스 파일명 흔적

후보 주소는 `추정`이며, 그 자체로 메커니즘 증거가 아니다.

### 3. 함수와 제어 흐름 복원

- 함수 시작과 끝을 확인한다.
- 조건 분기, 루프, 점프 테이블과 간접 호출을 복원한다.
- 디컴파일 결과를 원본 명령어와 교차 확인한다.
- 호출 규약, 인수, 반환값과 변경되는 레지스터·메모리를 기록한다.
- 오류·조기 반환·비활성 레코드 같은 실패 경로를 생략하지 않는다.

### 4. 자료구조 복원

- 같은 베이스 포인터에 대한 필드 접근을 모은다.
- 생성·초기화·읽기·쓰기·파괴 경로를 교차 확인한다.
- 필드 크기와 signedness를 명령어에서 확인한다.
- 서로 다른 레코드와 런타임 객체의 오프셋을 합치지 않는다.
- 의미가 불확실한 필드는 역할 이름 대신 `field_0xNN`으로 유지한다.

### 5. 동작 명세

다음을 의사코드나 상태 전이표로 작성한다.

- 입력 상태
- 모든 조건
- 계산 순서
- 변경되는 상태
- 호출되는 후속 동작
- 반환값
- 경계값과 실패 경로

### 6. 재현

원본 자료구조를 흉내 낸 입력을 만들고 다음을 검사한다.

- 반환값
- 변경된 필드와 전역 변수
- 생성·삭제된 레코드
- 호출된 후속 함수 또는 이벤트
- 호출 순서와 타이머

가능하면 순수 계산 함수를 원본 x86 코드에서 격리 실행한다. 불가능하면 정적 명세에서 독립 참조 구현을
만들고, 포팅 구현과 동일 입력으로 비교한다.

### 7. 이식

- 분석 문서와 테스트 벡터를 먼저 확정한다.
- 기존 구현과의 차이를 기록한다.
- 검증된 동작만 해당 도메인 계층에 반영한다.
- 화면을 맞추기 위한 일회성 보정값을 추가하지 않는다.

## 메커니즘 보고서 필수 항목

각 `mechanics/` 문서는 다음 항목을 가진다.

1. 질문과 범위
2. 원본 파일과 해시
3. 분석 상태
4. 함수·데이터 주소
5. 자료구조 필드
6. 제어 흐름과 수식
7. 확인된 사실
8. 추정과 미확인 항목
9. 재현 테스트 벡터
10. 현재 구현과의 차이
11. 다음 분석 작업

## 금지하는 지름길

- 문자열이나 함수명이 존재하므로 동작이 같다고 판정
- 미리 정한 주소의 바이트가 같으므로 사람이 붙인 의미를 확정
- 짧은 코드 창을 선형 스캔해 전체 함수 인수로 해석
- 현재 구현 테스트를 원본 동작 테스트로 해석
- 스크린샷이나 체감 속도로 수치 결정
- 동적 캡처 한 번으로 전체 분기와 자료구조를 일반화

## 동적 분석

동적 분석은 기본 단계가 아니다. 필요한 경우
[동적 검증 예외 지침](../agent-guides/dynamic-validation.md)을 적용한다. 정적 분석 없이 게임을 먼저
조작하고 화면을 따라가는 방식은 사용하지 않는다.
