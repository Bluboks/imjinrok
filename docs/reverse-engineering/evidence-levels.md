# 증거 및 상태 기준

## 목적

`검증됨`, `완료`, `원작 일치`가 서로 다른 의미로 사용되는 일을 막는다. 분석 상태, 재현 상태와 구현
상태를 별도로 기록한다.

## 분석 상태

| 상태 | 의미 | 허용되는 주장 |
| --- | --- | --- |
| `미확인` | 분석하지 않았거나 근거가 없음 | 질문과 조사 필요성만 기록 |
| `추정` | 주소·문자열·부분 코드로 유력한 해석이 있음 | 후보 역할과 불확실성 기록 |
| `정적 확정` | 관련 제어 흐름, 데이터 흐름, 필드와 상수가 원본에서 확인됨 | 명시한 범위의 원본 규칙 설명 |
| `반증됨` | 원본 코드나 데이터가 기존 해석과 모순됨 | 폐기된 가정과 반증 근거 기록 |

`정적 확정`은 함수 이름을 정확히 알아냈다는 뜻이 아니다. 문서가 다루는 질문에 필요한 모든 관련
분기와 상태 변경을 설명할 수 있다는 뜻이다.

## 재현 상태

| 상태 | 의미 |
| --- | --- |
| `미재현` | 독립 입력·출력 검증이 없음 |
| `부분 재현` | 정상 경로 일부만 재현 |
| `재현 완료` | 정상·경계·실패 경로가 테스트 벡터로 재현됨 |

## 구현 상태

| 상태 | 의미 |
| --- | --- |
| `없음` | 대응 구현이 없음 |
| `프로토타입` | 플레이 목적의 임시 또는 프로젝트 자체 구현 |
| `부분 이식` | 정적 확정된 규칙 일부를 반영 |
| `원본 기반` | `정적 확정`과 `재현 완료`를 만족하는 범위를 이식 |
| `의도적 적응` | 원본과 다른 웹 환경 설계를 명시적으로 채택 |
| `프로젝트 전용` | 원작에 대응 항목이 없는 프로젝트 기능 |

## 원작 일치 표기 조건

메커니즘을 원작과 일치한다고 표시하려면 다음을 모두 만족해야 한다.

- 분석 상태가 `정적 확정`
- 재현 상태가 `재현 완료`
- 원본 파일 해시와 함수·데이터 주소가 기록됨
- 현재 구현이 같은 테스트 벡터를 통과함
- 알려진 차이와 웹 적응이 별도로 기록됨

동적 캡처는 위 조건을 대체하지 않는다.

## 자원 매핑 판정

PNG가 존재하고 렌더링된다는 사실과 원본 의미가 맞다는 사실을 분리한다.

| 확인한 항목 | 인정되는 범위 |
| --- | --- |
| 변환 매니페스트에 프레임이 존재 | 자원 변환·경로의 구문 확인 |
| EXE 자원 테이블이 `SPR` 경로를 가리킴 | 엔티티 종류와 자원 후보 |
| 상태·방향·체력·ID에서 프레임으로 가는 전체 정적 경로 | 해당 의미 매핑의 `정적 확정` 후보 |
| 현재 화면에서 자연스럽게 보임 | 분석 상태에 영향 없음 |

방향, 행동, 건물 체력 단계, 초상화 인물 정체는 서로 독립된 주장이다. 한 항목을 확인해도 나머지
항목의 상태는 자동으로 올라가지 않는다.

## 기존 문서 이관

과거 문서의 표현은 다음처럼 다시 분류한다.

- 단순 문자열·바이트 존재: `추정`
- 짧은 코드 구간의 수동 해석: 기본적으로 `추정`
- 전체 관련 분기와 필드가 확인된 정적 분석: 검토 후 `정적 확정`
- 현재 구현의 문자열·테스트 존재: 원본 분석 상태에 영향 없음
- 원시 파일이 없는 VM 관찰: 보조 기록이며 재현 상태에 포함하지 않음
- 조건을 강제로 패치한 런타임 결과: 해당 경로의 보조 증거이며 자연 조건 전체의 증거가 아님

## 상태 변경 규칙

- 상태를 올릴 때 근거 링크와 검토자를 기록한다.
- 새 반례가 나오면 즉시 `추정` 또는 `반증됨`으로 내린다.
- 문서 분량이나 테스트 개수는 상태 승격 근거가 아니다.
