# 스프라이트 매핑 감사

기준일: 2026-07-28

## 판정

원본 내부 클래스 1~95의 명칭·슬롯·기본 프레임·자원 경로를 전수 정적 확정했다. 현행 21개
비주얼 중 19개는 원본 타입 하나와 고유하게 연결된다. 조선 본영과 봉화대의 건설·정상·반파 본체는
`scoped-static-proven`, 정체와 일부 또는 미확정 프레임이 함께 있는 17개는 `mixed`다.
`farmerk.spr`는 두 타입이 공유하고 `advtowerj.spr`는 95개 타입 정의에 사용되지 않아 두 비주얼만
`unverified`다. `mixed`인 조선 창병 비주얼에서는 상태 1 일반 이동을, 일본 사무라이와
권율·유성룡 비주얼에서는 각 문서가 확인한 상태 8 idle·1 일반 이동·4 공격·7 사망을,
일본 귀갑차에서는 상태 8/1/4의 grid 방향만 정적 확정 범위로 승격했다.
브리핑 `SPEECH` 초상화 17개는 `static-proven`을 유지한다.

기계 생성 상세는
[`analysis/generated/sprite-mapping-audit.json`](../../analysis/generated/sprite-mapping-audit.json)에
있다. 다음 명령으로 현재 코드와 원본 자원 해시에서 재생성한다.

```bash
pnpm imjinrok:audit-sprite-mappings
```

## 확인된 결함과 위험

### 유닛

- `swordj.spr`는 클래스 3 `일본 창병`, `archerk.spr`는 클래스 4 `조선 궁수`,
  `gunj1.spr`는 클래스 12 `일본 조총병`으로 정체·출처가 확정됐다.
- 과거 권율과 유성룡은 클래스 79 `조선 사명대사`의 `generalk4.spr`를 공유했다. 현재는 권율을
  클래스 76 `generalk11.spr`, 유성룡을 클래스 78 `generalk31.spr`로 분리했다.
- `farmerk.spr`는 클래스 7 `조선 농부`와 클래스 93 `솜씨 좋은 도공`이 공유하므로 자원 경로만
  보고 현재 `villager`의 정체를 하나로 확정하지 않는다.
- 공통 방향 순서를 `s, sw, w, nw, n, ne, e, se`로 고정했다.
- 다수 유닛은 원본 다섯 방향을 `n, ne, e, se, s`로 가정하고 나머지 세 방향을 좌우 반전한다.
- 이 방향 순서와 미러링 방식에 원본 바이너리·데이터 근거가 연결돼 있지 않다.
- 조선 창병의 `move`·`walk`는 예외다. 원본 이동 ΔX·ΔY와 현재 격자 `+X=동`, `+Y=남`을
  연결해 frame 0~39의 방향·mirror를 이식했으며 해당 두 상태의 방향·미러 차단 finding을 제거했다.
- 조선 창병의 `idle`과 `attack`은 여전히 위 공통 추정 매핑을 사용하며 차단 finding을 유지한다.
- 권율은 `generalk13.spr` idle, `generalk11.spr` 이동·사망, `generalk12.spr` 공격을,
  유성룡은 `generalk31.spr` idle·이동, `generalk32.spr` 공격·사망을 사용한다. 각 상태의
  8방향·phase·mirror를 정적 방향식으로 이식했다. 두 영웅의 원본 효과 phase는 7로 후속
  확정했지만 프로젝트 공격 이벤트와 클립 FPS 연결은 아직 잠정값이다.
- 일본 조총병의 `attack`은 `move`·`walk`와 완전히 같은 프레임 클립을 사용한다.
- 일본 사무라이는 `horseswordj1.spr`·`horseswordj2.spr`의 상태 8/1/4/7 frame·방향·mirror를
  [별도 파일럿](mechanics/k01-samurai-animation-pilot.md)에서 확정·이식했다. 귀갑차는
  [class 14 파일럿](mechanics/k01-turtle-tank-animation-pilot.md)의 상태 8/1/4 grid
  frame·mirror를 이식했다. 고니시는 [class 82 파일럿](mechanics/k01-konishi-animation-pilot.md)의
  `generalj12/11/13/11.spr` 상태 8/1/4/7 grid frame·mirror를 이식했다.
  세 visual의 FPS 또는 render size·pivot은 프로젝트 잠정값이다.

따라서 사용자가 보고한 “유닛 프레임 방향이 맞지 않음”은 현재 코드 구조로 설명된다. 개별 프레임을
눈으로 다시 배치하는 대신, 원본 상태·방향 값에서 프레임을 선택하는 테이블과 수식을 복원해야 한다.

### 건물

- 건설 프레임을 0부터 임의의 `completeFrameIndex`까지 연속 범위로 잡는다.
- idle 프레임은 그 끝 또는 별도 하드코딩 번호로 선택한다.
- 본체와 깃발·불꽃 같은 오버레이 구분도 프레임 위치로 추정했다.
- 조선 본영과 봉화대를 제외하면 현재 체력·최대 체력·건설 진행도에서 프레임을 선택하는 확정 경로가
  없다.

조선 본영은 기존 idle frame 8이 원본의 반파 이미지임을 확인해 정상 frame 7로 수정했고, 진행도
`0/10/20/30/40/50/70/100`과 엄격한 체력 50% 미만 분기를 이식했다.

기존 봉화대의 `towerk.spr`는 실제로 클래스 42 `조선 화포망루`였다. 클래스 52
`조선 봉화대`의 `firehousek.spr`로 교체하고 정상 frame 7·반파 frame 8과 같은 건설 경계를
독립 교차 확인했다. 다른 건물에는 이 결과를 복사하지 않는다. 상세 근거는
[조선 본영 파일럿](mechanics/building-state-pilot.md)과
[조선 봉화대 파일럿](mechanics/beacon-state-pilot.md)에 있다.

`advtowerj.spr`는 원본 스프라이트 표에는 있지만 95개 타입 정의의 본체 자원으로 사용되지 않는다.
현재 `japanese-camp-advanced-tower` 의미는 계속 `unbound`다.

## 정적 복원 순서

1. 완료: 클래스 1~95의 원본 이름·슬롯·기본 프레임·flags·SPR 경로를 전수 연결한다.
2. 완료: 내부 클래스 2→`조선 창병`→슬롯 100→`char\swordk.spr`와 상태 1·2 이동 프레임 식을 연결한다.
3. 완료(일반 이동): 상태 1 일반 방향·미러를 `move`·`walk`에 이식한다.
4. 진행 중: 상태 2 통합, 상태 1 특수 `+0x1e8` 분기의 클래스 2 초기화와 전투 상태를 연결한다.
5. 완료(핵심 상태 프레임): 권율·유성룡의 상태 8 idle·1 일반 이동·4 공격·7 사망에 고유 자원,
   8방향·phase·mirror를 연결했다. 효과 phase 7·사이클·회복은 후속 전투 파일럿에서 완료했으며
   원본 틱→FPS 변환·피격·사망 표시 수명은 남아 있다.
6. 완료(본체): 조선 본영과 봉화대의 건설 진행도·체력에서 frame 0~8 선택을 연결한다.
7. 완료: `SPEECH` 레코드 소비자부터 `hero.spr` 프레임 주소 계산까지 연결한다.
8. 원본 입력 값과 기대 프레임을 담은 독립 테스트 벡터가 완결된 범위만 `themes.ts`에 이식한다.

상세 작업 규칙은
[스프라이트·애니메이션 매핑 지침](../agent-guides/sprite-animation-mapping.md)을 따른다.

## 이번 정적 분석에서 확보한 시작점

- `0x0041d470`과 `0x0041d560`은 main entity `+0x0a`의 sprite slot을 각각 `+0x456`,
  `+0x48e` 계열 설정에서 고르는 후보 함수다. 작은 draw 레코드의 `+0x0a` frame 필드와 혼동하지
  않는다.
- `0x0041d210`은 main entity `BYTE +0x03`을 상태 switch 입력으로 사용한다. 상태 1·2는
  `0x0041efa0`, `0x0041f380`으로 이어진다.
- 내부 클래스 2 초기화 경로는 슬롯 100과 두 상태의 phase 수 8, frame base를 설정한다.
- `FUN_0045bf50`의 95개 writer 호출, `FUN_0048ea90`의 CP949 이름 복사와 슬롯별 자원 포인터를
  결합해 전체 [엔티티 타입 카탈로그](data-structures/entity-type-catalog.md)를 생성했다.
- 슬롯 100의 원본 경로는 `char\swordk.spr`이며 60×60, 192프레임이다.
- 상태 1은 frame base `0, 8, 16, 24, 32`, 상태 2는 `88, 96, 104, 112, 120`을 방향값과
  mirror 분기에 따라 선택한다. 전체 식은
  [조선 창병·내부 클래스 2 애니메이션 파일럿](mechanics/unit-animation-pilot.md)에 기록했다.
- `0x00425b20`은 이동 중 `BYTE +0xba` 값에 따라 상태 1 또는 2를 쓴다. 두 상태가 이동
  비주얼이라는 의미와 상태 1 일반 분기는 확정했다.
- 클래스 76은 슬롯 155 `generalk13.spr`를 상태 8 idle, 슬롯 153 `generalk11.spr`를 상태 1
  이동과 상태 7 사망, 슬롯 154 `generalk12.spr`를 상태 4 공격에 사용한다. 클래스 78은 슬롯
  158 `generalk31.spr`를 idle·이동, 슬롯 159 `generalk32.spr`를 공격·사망에 사용한다.
  자세한 방향·phase 경로는
  [K01 권율·유성룡 핵심 애니메이션 파일럿](mechanics/k01-hero-animation-pilot.md)에 기록했다.
- 클래스 13 일본 사무라이는 slot 118 `horseswordj2.spr`를 상태 8 idle에, slot 117
  `horseswordj1.spr`를 상태 1 이동·상태 4 공격·상태 7 사망에 사용한다. 방향·phase 식은
  [K01 일본 사무라이 핵심 애니메이션 파일럿](mechanics/k01-samurai-animation-pilot.md)에
  기록했다.
- 상태 1 특수 분기는 `WORD +0x1e8`과 특수 방향 값 1000~1007까지 구조를 복원했다. 하지만
  클래스 2 초기화가 특수 분기에 필요한 base 네 개를 설정하지 않으므로 현재 도구는 이 입력을 거부한다.
- 내부 클래스 49는 `조선 본영`, 슬롯 141, `char\hqk.spr`로 식별했다. 건설 진행도는
  frame 0~7, 완공 정상은 7, 유효 체력이 50% 미만이면 8을 선택한다.
- 내부 클래스 52는 `조선 봉화대`, 슬롯 113, `char\firehousek.spr`다. 공통 건물 본체 경로와
  damage flag를 교차 확인해 frame 0~8을 같은 범위로 확정했다.
- `0x00482590`은 `SPEECH`를 포함한 11개 스크립트 명령 이름을 비교해 0부터 10까지의 명령 번호를
  반환한다.
- `0x00482860`의 case 0이 `SPEECH` 레코드를 만든다. 네 인수를 읽어 첫 문자열을 보존하고, 세 번째
  인수로 `script\\eft\\%s.YAV` 경로를 만들며, 네 번째 문자열을 복사한 뒤 `0x882`바이트 레코드를
  큐에 넣는다.
- `FUN_004824c0`과 `FUN_004830f0`은 종류 0 레코드를 소비해 인물 ID, 표시 슬롯, 음성 경로와
  대사를 `FUN_004a7b10`에 전달한다.
- `FUN_004a7690`은 `FUN_004a8870`의 ID 조회 결과로 `0x004c91ac`의 17개 WORD 프레임 표를
  읽고, `hero.spr` 오프셋 표와 데이터 베이스로 최종 프레임 주소를 계산한다.
- 정적 결과는
  `K1→6`, `K2→11`, `K3→8`, `K4→9`, `K5→7`, `J1→4`, `J2→2`, `J3→3`,
  `J4→1`, `J5→0`, `C1→5`, `C2→14`, `C3→13`, `C4→10`, `C5→12`,
  `K10→15`, `K6→17`이다.
- ID 불일치 시 조회 함수는 `-1`을 반환한다. 포팅 구현은 미등록 ID의 초상화를 표시하지 않는다.

타입 카탈로그의 이름·자원 연결, 초상화 표, 조선 창병의 상태 1 일반 이동, 권율·유성룡의 네 핵심
