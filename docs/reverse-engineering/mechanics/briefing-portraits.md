# 브리핑 `SPEECH` 초상화 매핑

기준일: 2026-07-26

## 질문과 판정

원본 스크립트의 `[SPEECH][인물 ID]...`가 어떤 자원과 프레임을 선택하는가?

판정은 `정적 확정`이다. 원본 EXE의 스크립트 레코드 소비자에서 인물 ID 조회, 정적 프레임 표,
`yfnt\hero.spr` 로드와 최종 프레임 주소 계산까지 하나의 호출·데이터 흐름으로 연결했다. 추출기와
클라이언트 매핑을 동일 원본으로 비교하는 테스트도 존재한다.

이 판정은 `SPEECH` 초상화 경로에만 적용한다. `portrait.spr`의 다른 용도나 유닛·건물 프레임 의미를
확정한 것이 아니다.

## 원본

| 파일 | SHA-256 | 확인된 형식 |
| --- | --- | --- |
| `original/imjinrok2/imjinrok2.exe` | `25a95d568082478ce0f50c89c9bbb9536ef33eb6904afa62903e9d63b7a5d03e` | PE32 x86 |
| `original/imjinrok2/yfnt/hero.spr` | `a701bd0a66ec30dfd0bbc33ad7e78b937e725292fd37e9cae983ca28ad6af853` | 130×120, 20프레임 |

EXE의 `0x004c91f4`에는 `yfnt\hero.spr` 문자열이 있고 `FUN_004a7410`이 이 자원을 로드한다.

## 제어 흐름

| 주소 | 확인한 동작 |
| ---: | --- |
| `0x00482590` | `SPEECH`를 명령 번호 0으로 해석 |
| `0x00482860` case 0 | 네 인수를 종류 0 큐 레코드로 변환 |
| `0x004824c0` | 큐 레코드를 소비해 `FUN_004830f0`으로 전달 |
| `0x004830f0` case 0, `0x00483115` | 인물 ID·표시 슬롯·음성 경로·대사를 `FUN_004a7b10`에 전달 |
| `0x004a7b10` | 대사 표시 경로를 조정하고 `FUN_004a7690` 호출 |
| `0x004a7690`, `0x004a76d0` | `FUN_004a8870`으로 인물 ID의 조회 인덱스를 구함 |
| `0x004a7690`, `0x004a774a` | `WORD [0x004c91ac + 조회 인덱스×2]`에서 프레임 번호를 읽음 |
| `0x004a7690`, `0x004a7758` | `hero.spr` 오프셋 표와 데이터 베이스로 프레임 주소를 계산해 그림 |
| `0x004a8870` | 17개 인물 ID를 순서대로 비교하고 일치 인덱스 또는 `-1` 반환 |

종류 0 레코드의 확인된 payload 필드는 다음과 같다.

| 오프셋 | 크기 | 의미 |
| ---: | ---: | --- |
| `+0x000` | 문자열 | 인물 ID |
| `+0x080` | WORD | 표시 슬롯 |
| `+0x082` | 문자열 | `script\eft\%s.YAV` 형식 음성 경로 |
| `+0x482` | 문자열 | 표시할 대사 |

## 정적 테이블과 결과

`FUN_0048ea90`은 `K1`~`K6`·`K10`, `J1`~`J5`, `C1`~`C5` 정적 문자열을 16바이트 간격
런타임 저장소에 복사한다.
`FUN_004a7410`은 그 저장소 포인터 17개를 조회 순서로 `0x00c83e00`에 등록한다. 같은 인덱스로
`0x004c91ac`의 WORD 표를 읽으면 다음 결과가 나온다.

| 1 | `K2` | 11 |
| 2 | `K3` | 8 |
| 3 | `K4` | 9 |

## 실패 경로

`FUN_004a8870`은 17개 항목 모두와 불일치하면 진단 호출 후 `AX = 0xffff`, 즉 signed WORD
`-1`을 반환한다. 이 반환부터 프레임 표 접근 사이에는 명시적 범위 검사가 보이지 않는다. 따라서 포팅
구현은 알 수 없는 ID를 임의 인물로 대체하지 않고 초상화를 표시하지 않는다. 원본의 후속 메모리 접근
결과는 이 문서 범위에서 별도로 일반화하지 않는다.

## 재현과 이식

- `tools/imjinrok/extract-mission-portrait-mapping.mjs`가 EXE 해시, 코드 anchor, ID 저장소,
  조회 포인터 표, 프레임 표와 `hero.spr` 헤더를 모두 검증해 17개 결과를 추출한다.
- `tools/imjinrok/mission-portrait-mapping.test.mjs`가 전체 표, `K1`·`K3`·`K10`·`J1`,
  실패값 `-1`과 결정론을 검사한다.
- `apps/game-client/src/missionPortraits.test.ts`가 클라이언트 표를 정적 추출 결과와 직접 비교하고,
  20개 PNG의 존재와 130×120 크기를 검사한다.
- `apps/game-client/src/missionPortraits.ts`는 확인된 17개 ID만
  `ui/mission-portraits/hero_NNNN.png`에 연결한다.

기존 구현의 `K1→portrait.spr 1`, `K3→3`, `K10→30`, `J1→75`는 이 경로와 자원 모두가
달라 제거했다.

숫자 표시 슬롯과 화면 좌표는 [`SPEECH` 대화 레이아웃](speech-layout.md)에 별도로 기록한다.
