# K01 팬 리마스터 MVP 정적 분석 계획

## 질문과 범위

K01 하나를 브리핑부터 승패 결과까지 원본 플레이 경험에 최대한 가까운 팬 리마스터 MVP로 완성한다.
K02는 이 문서와 단기 완료 조건에 포함하지 않는다.

이 문서는 그중 미션 스크립트와 승패 메커니즘을 원본 바이너리만으로 복원하는 파일럿을 다룬다.
전체 K01 MVP 완료 조건은 [로드맵](../../../roadmap.md)에 있으며, 이 파일럿 완료만으로 K01 전체를
완료로 판정하지 않는다.

정적 분석 대상은 다음과 같다.

- 시작·중간 스크립트 실행 조건
- 완성된 봉화대 검색
- K0120의 일회성 실행과 후속 효과
- 보호 영웅 손실 조건
- 승리·패배 타이머와 결과 전환

UI 배치, 대사 표시 타이밍과 애니메이션은 이 문서의 현재 범위가 아니다.

## 입력 기준

- 실행 파일: `original/imjinrok2/imjinrok2.exe`
- SHA-256: `25a95d568082478ce0f50c89c9bbb9536ef33eb6904afa62903e9d63b7a5d03e`
- 분석 상태: 봉화대→K0120 trigger와 K01 loss latch→timer→result commit 단위 `정적 확정`
- 재현 상태: 위 두 독립 단위 `재현 완료`
- 구현 상태: `프로토타입`

두 상태 승격은 봉화대 trigger와 결과 lifecycle 전용 추출기가 각각 전체 관련 CFG·call edge·
reference·byte anchor와 정상·경계·실패 합성 벡터를 검증한 범위에만 적용한다.

Ghidra 자동 분석은 K0120 검사 지점 `0x0048a731`과 영웅 손실 검사 지점 `0x0048a812`를 모두
`FUN_0048a5c0`(`0x0048a5c0-0x0048a878`, CFG 32개, 명령어 181개)에 포함했다. 이 경계와 전체
명령어·디컴파일 결과는 `analysis/generated/imjinrok2/seeds.json`에 재현 가능하게 저장돼 있다.
이는 포함 함수의 탐색 범위를 고정하지만 아래 역할 해석을 자동으로 확정하지는 않는다.

## 원본 자원

- `script\k0110`
- `script\k0115`
- `script\k0120`
- `stagemap\k01.map`

스크립트 파일은 원본 데이터에서 직접 파싱할 수 있다. 실행 순서와 조건은 바이너리의 캠페인 핸들러로
확인해야 한다.

## K0120 봉화대 경로

이 단위의 상세 근거는
[K01 봉화대 완성·K0120 native trigger](../k01-beacon-k0120-trigger.md)에 둔다.
`0x00487fa0` raw-relation blocker와 `WORD 0x008438dc`가 모두 0일 때만
`0x00635258`의 `0x558`-byte record 1,200개를 scan한다. active lookup 뒤 signed
`BYTE +0x38 == WORD current player`, class `+0x37 == 52`, progress `+0x8c == 100`을
모두 요구한다.

match는 flag를 먼저 1로 쓴다. script context `+4`가 nonzero이면 load/start만 건너뛰고,
그렇지 않으면 `script\k0120` loader의 `0/1` 반환을 검사하지 않고 void start를 호출한다. 이어 signed-WORD
descriptor 증원, selector 5 raw grid 변경과 두 raw global writer를 항상 정해진 순서로 호출한다.
loop에 break가 없어 같은 initial scan의 복수 match는 이 블록을 반복한다. scan 뒤 flag가 정확히
1이고 script context `+8`이 0일 때만 1을 caller로 넘긴다.

이 범위에서 아직 확인되지 않은 것은 flag reset lifecycle과 native raw state의 사람용 의미다.
반환 1과 공통 결과 timer/commit 연결은
[K01 미션 결과 수명주기](../k01-mission-result-lifecycle.md)에서 별도 확정했다.

## 보호 영웅과 패배 경로

상세 근거와 합성 벡터는
[K01 미션 결과 수명주기](../k01-mission-result-lifecycle.md)에 둔다. 이 문서에서는 연결점만
요약한다.

- `0x0048a812` 부근에서 현재 소유자의 타입 `0x4c`을 조회한다.
- `0x0048a840` 부근에서 같은 방식으로 타입 `0x4e`을 조회한다.
- `0x004885e0`은 owner/class 목록의 low-WORD slot을 `0x00441db0`으로 검사하고 일치
  record의 full reference를 반환한다. `0x00441de0`은 slot table nonzero, runtime entity
  signed health `+0x3e > 0`, full reference low/high WORD 일치를 순서대로 확인한다.
- 대상이 존재하지 않거나 살아 있지 않다고 판단되고 `DWORD [0x00843740] == 0`이면 현재 틱 후보
  `DWORD [0x00882e04]`를 패배 타이머에 기록한다.

K01 시작 레코드와 타입 카탈로그를 교차 확인한 매핑은 다음과 같다.

- 타입 `0x4c`: 내부 클래스 76 `조선 권율`, `generalk11.spr`
- 타입 `0x4e`: 내부 클래스 78 `조선 유성룡`, `generalk31.spr`

두 영웅의 상태 1 일반 이동뿐 아니라 상태 8 idle, 상태 4 공격, 상태 7 사망의 슬롯·프레임·방향은
[K01 권율·유성룡 핵심 애니메이션 파일럿](../k01-hero-animation-pilot.md)에서 정적
확정·이식했다. [K01 영웅 일반 공격 파일럿](../k01-hero-basic-attack-pilot.md)에서는 두 영웅의
효과 phase 7, 사이클 종료와 회복, 권율 직접 피해와 유성룡 투사체 생성까지 정적 확정·재현했다.
[K01 유성룡 투사체 subtype `0x0c` 파일럿](../k01-ryu-projectile-pilot.md)에서는 생성 뒤
보수적인 좌표 accepted subset `0..32767`의 14-step 정수 경로, 도착 시 저장 대상 충돌,
effect kind 9 피해와 레코드 반환까지 정적 확정·재현했다. 원본 caller 전체 signed-WORD 좌표
범위와 원본 좌표 변환은 미확정이다.
[K01 권율·유성룡 대상 선택과 사거리](../k01-hero-targeting-range.md)는 공격 전 대상 경계를,
[K01 영웅 사망 수명주기](../k01-hero-death-lifecycle.md)는 signed health 0의 즉시 alive
실패, incoming cadence/runtime flags별 행동 6/7 phase, 조건부 active slot 해제와 확인한
경로의 stale target reference 수명을 정적 확정·재현했다.
상태별 정확한 초 단위 재생 속도와 프로젝트 24 Hz·identity mapping은 계속 미확정이다.

## 공통 결과 판정

`FUN_0048d6f0`은 win timer를 먼저 검사하고, zero sentinel을 건너뛴 뒤 wrapped DWORD
subtraction과 `CDQ/XOR/SUB`, signed `JLE`를 사용한다. signed absolute bit pattern이
`0x7d0`보다 엄격히 클 때 win 1 또는 loss `-1`이다. win 성숙이 동시 loss보다 우선하고,
win 미성숙 뒤 loss 성숙은 `-1`이다.

`FUN_0048ddb0`은 세 raw WORD pre-gate 뒤 timer를 stage보다 먼저 검사한다. timer 결과만
`FUN_004492f0`의 `DWORD 0x0055299c=1` write를 거치며, timer가 0일 때 signed stage selector
1이 K01 updater로 간다. `FUN_004481d0`은 raw global tick이 cache와 다를 때만 cache를 먼저
쓰고 dispatcher를 호출한 뒤 AX `1/0xffff`를 result code `0x18/0x1a`와
`FUN_00446420` 호출로 연결한다.

## 재현 테스트 계획

### 봉화대

- 레코드가 없으면 K0120을 실행하지 않는다.
- 다른 소유자의 완성 봉화대는 무시한다.
- 현재 소유자의 미완성 봉화대는 무시한다.
- 현재 소유자의 타입 `0x34`, 진행도 `0x64` 레코드만 트리거한다.
- 일회성 플래그가 이미 설정되면 다시 실행하지 않는다.
- 비활성 레코드가 같은 필드 값을 가져도 무시한다.

### 패배

- 두 보호 영웅이 살아 있으면 타이머를 설정하지 않는다.
- 각 영웅의 부재 조건을 독립적으로 확인한다.
- 패배 타이머는 처음 한 번만 설정되는지 확인한다.
- `0x7d0` 직전, 같은 값, 직후의 반환을 확인한다.
- 승리·패배 타이머 동시 설정을 확인한다.

## 파일럿 완료 조건

- 관련 함수 경계와 전체 제어 흐름이 저장된다.
- 사용하는 전역과 구조체 필드가 함수 지도와 자료구조 문서에 연결된다.
- 위 테스트 벡터가 독립 참조 구현 또는 원본 함수 격리 실행으로 재현된다.
- 현재 프로젝트가 동일한 벡터를 통과한다.
- 남은 추정이 파일럿 범위의 결과에 영향을 주지 않는다.
