# 정적 분석 중심 로드맵

## 목표

VM에서 원본 게임을 플레이하며 화면 변화를 따라가는 방식을 기본 작업에서 제거한다. 원본 바이너리의
제어 흐름, 자료구조와 수식을 정적으로 복원하고, 독립 테스트로 재현한 뒤 웹 프로젝트에 이식한다.

진행률은 기간이나 작성된 코드량이 아니라 각 단계의 통과 조건으로 판단한다.

## 현재 진행

- 0단계: 완료. [분석 도구 인벤토리](reverse-engineering/tool-inventory.md)에 모든 기존 도구를
  `유지`, `재검증`, `보관`으로 분류했다.
- 1단계: 완료. 고정 도구 설치, 원본 해시 강제, 함수·호출 관계·문자열·일반 메모리 참조·간접
  분기·점프 테이블·seed CFG·명령어·디컴파일 내보내기와 2회 결정론 검증을 완료했다.
- 2단계: 진행 중. 스프라이트 매핑 감사를 수행해 16개 엔티티 비주얼은 `미검증`으로 격리했고,
  `SPEECH` 초상화 17개는 정적 복원·테스트·이식을 완료했다.
- 3단계 이후: 시작 전. 자동 함수 경계와 후보 주소가 있으며 메커니즘 역할은 아직 `추정`이다.

## 0단계: 기존 산출물 분류

- 기존 데이터 파서, 증거 도구, 구현과 문서를 목록화한다.
- 원본 파일을 직접 해석하는 도구와 의미를 미리 가정한 도구를 구분한다.
- 과거 VM 중심 문서는 `docs/archive/`에서 보존한다.

통과 조건:

- 모든 기존 분석 산출물에 `유지`, `재검증`, `보관` 중 하나의 상태가 부여된다.

## 1단계: 정적 분석 파이프라인

- Ghidra 기반 프로젝트를 동일한 설정으로 반복 생성할 수 있게 한다.
- 함수 경계, 호출 관계, 문자열 참조, 전역 변수와 점프 테이블을 내보낸다.
- 분석 입력과 산출물에 원본 실행 파일 해시를 포함한다.
- 수동으로 만든 간이 x86 디코더를 의미 복원의 기반으로 사용하지 않는다.

통과 조건:

- 깨끗한 환경에서 같은 함수·참조 목록을 재생성할 수 있다.
- 분석 산출물에서 원본 주소와 바이트 범위를 역추적할 수 있다.

## 2단계: 공통 함수와 자료구조

- 메인 루프와 게임 틱
- 엔티티·유닛·건물 레코드
- 플레이어와 소유권
- 맵과 좌표
- 행동·명령 큐
- 캠페인 스크립트 실행기
- 공격과 투사체
- 애니메이션 상태

통과 조건:

- 주요 필드가 생성·읽기·쓰기 경로에서 교차 확인된다.
- 동일 오프셋을 서로 다른 구조체의 필드로 혼동하지 않는다.

### 2A: 스프라이트 매핑 복구 파일럿

사용자에게 직접 드러난 오매핑을 우선 차단하기 위해 다음 세 질문을 병행하지 않고 순서대로 푼다.

1. 유닛 한 종류의 엔티티 종류·행동·방향→프레임 식
2. 건물 한 종류의 건설·정상·피해→본체·오버레이 프레임 식
3. `SPEECH` 초상화 ID→자원·프레임 식 — 완료: `hero.spr`의 17개 ID 표

통과 조건:

- 자원 경로, 상태 값, 방향·체력·ID 값과 최종 프레임이 하나의 정적 데이터 흐름으로 연결된다.
- 기본 분기, 범위 밖 입력과 미러링을 포함한 테스트 벡터가 있다.
- 감사 보고서에서 증명한 항목만 `정적 확정`으로 승격한다.
- 확정된 벡터를 적용하기 전에는 현행 프레임 번호를 손으로 보정하지 않는다.

## 3단계: K01 파일럿

- K0110·K0115·K0120 호출 흐름
- 봉화대 검색과 완성 조건
- 원샷 플래그와 후속 효과
- 보호 영웅 생존 조건
- 승리·패배 타이머와 결과 전환

통과 조건:

- 관련 함수의 전체 분기와 데이터 흐름을 설명할 수 있다.
- 합성 엔티티 입력으로 스크립트 호출과 승패 결과를 재현한다.
- 원본에 없는 추정값이 테스트 기대값에 포함되지 않는다.

## 4단계: 공격 주기 파일럿

유닛 한 종류에 대해 대상 선택부터 다음 행동까지 복원한다.

1. 대상 검색과 유효성 판정
2. 이동과 사거리 판정
3. 공격 상태 진입
4. 타격 프레임과 피해 시점
5. 공격력·방어력·속성 계산
6. 투사체 또는 즉시 피해
7. 사망과 대상 참조 정리
8. 재사용 대기와 다음 상태

통과 조건:

- 경계 사거리, 최소 피해, 대상 소멸과 공격 취소를 포함한 테스트 벡터가 있다.
- 화면 관찰 없이 상태 전이와 결과를 재현한다.

## 5단계: 적합성 테스트

- 원본 주소와 입력 상태가 포함된 테스트 벡터 형식을 만든다.
- 반환값뿐 아니라 메모리 변경, 후속 호출과 이벤트 순서를 검사한다.
- 격리 실행이 가능한 원본 함수는 에뮬레이션을 우선 검토한다.
- 현재 구현의 문자열이나 함수 존재 여부를 원작 검증으로 사용하지 않는다.

통과 조건:

- 원본 분석 결과와 포팅 구현을 동일한 입력으로 비교할 수 있다.

## 6단계: 검증된 단위 이식

- 검증된 메커니즘과 현재 구현의 차이를 먼저 기록한다.
- 임시 보정이 아니라 해당 도메인 계층에서 기존 구현을 교체한다.
- 분석 문서와 테스트 벡터를 구현 테스트에 연결한다.
- 불필요해진 추정 상수와 fallback을 제거한다.

통과 조건:

- 해당 메커니즘이 `원본 기반`으로 표시되고 회귀 테스트가 통과한다.

## 7단계: 범위 확장

다음 순서로 진행한다.

1. 데이터 포맷과 엔티티 정의
2. 자원·생산·건설·연구
3. 이동·충돌·경로 탐색
4. 공격·투사체·피해·사망
5. 명령 큐와 상태 머신
6. 캠페인
7. AI
8. 애니메이션
9. 카메라·선택·입력
10. HUD와 메뉴
11. 음향과 연출

## 8단계: 제한적인 동적 검증

동적 분석은 [동적 검증 예외 지침](agent-guides/dynamic-validation.md)의 조건을 모두 만족할 때만 수행한다.
게임 플레이 재현은 하지 않고, 저장 상태와 사전 설치한 브레이크포인트로 질문 하나만 확인한다.

동적 검증은 각 단계의 기본 통과 조건이 아니다.

## 재평가 지점

- K01 파일럿 완료 후 정적 분석 방법의 재현성과 비용을 평가한다.
- 공격 주기 파일럿 완료 후 실시간 상태 머신까지 같은 방법을 확장할지 평가한다.
- 파일럿이 실패하면 VM 플레이 방식으로 돌아가지 않고 정적 분석 도구·함수 경계·자료구조 가정을 먼저
  재검토한다.
