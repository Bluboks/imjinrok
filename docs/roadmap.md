# 정적 분석 중심 로드맵

## 단기 제품 목표

조선 캠페인 K01 하나를 원본 플레이 경험에 최대한 가까운 팬 리마스터 MVP로 완성한다. 원작 팬이
브리핑부터 승리·패배 결과까지 플레이하고, 원본의 맵·등장인물·유닛·건물·스크립트 흐름·UI·음향을
알아볼 수 있는 하나의 수직 단면이 결과물이다.

K02는 K01 완료 뒤의 후속 마일스톤이다. K02 코드와 자료가 이미 있어도 K01의 완료 판정이나 현재
우선순위에 포함하지 않는다.

## 분석 원칙

VM에서 원본 게임을 플레이하며 화면 변화를 따라가는 방식을 기본 작업에서 제거한다. 원본 바이너리의
제어 흐름, 자료구조와 수식을 정적으로 복원하고, 독립 테스트로 재현한 뒤 웹 프로젝트에 이식한다.

진행률은 기간이나 작성된 코드량이 아니라 각 단계의 통과 조건으로 판단한다.

## 현재 진행

- 0단계: 완료. [분석 도구 인벤토리](reverse-engineering/tool-inventory.md)에 모든 기존 도구를
  `유지`, `재검증`, `보관`으로 분류했다.
- 1단계: 완료. 고정 도구 설치, 원본 해시 강제, 함수·호출 관계·문자열·일반 메모리 참조·간접
  분기·점프 테이블·seed CFG·명령어·디컴파일 내보내기와 2회 결정론 검증을 완료했다.
- 2단계: 진행 중. 초기 스프라이트 매핑 감사에서 16개 엔티티 비주얼을 `미검증`으로 격리했다.
  이후 `SPEECH` 초상화 17개와 핵심 대화 레이아웃, 조선 본영의 건설·정상·반파 본체 프레임을
  정적 복원·테스트·이식했다. 내부 클래스 2는 `조선 창병`으로 식별했으며 상태 1·2가 이동
  비주얼임을 확인하고 상태 1 일반 이동의 방향·미러를 이식했다. 내부 클래스 1~95의 원본 정체와 자원
  경로도 전수 복원했으며, 잘못 연결된 조선 봉화대를 `firehousek.spr`와 본체 frame 0~8로
  교체했다. K01 권율·유성룡도 전용 `generalk11/12/13.spr`·`generalk31/32.spr`와 상태 8
  idle·1 일반 이동·4 공격·7 사망의 프레임·방향·미러를 복원해 사명대사 공유 비주얼과 임시
  상태 프레임을 제거했다. 두 영웅의 일반 공격 효과 phase·사이클 종료·회복 카운터도 정적
  복원했으며 권율 직접 피해와 유성룡 subtype `0x0c`의 생성·보수적인 port accepted 좌표 subset
  `0..32767` 비행·도착 충돌·effect kind `9` WORD 피해·raw 적용 gate·실패 경로까지 재현했다.
  원본 caller 전체 signed-WORD 좌표 범위와 원본 좌표·틱의 프로젝트 변환은 다음 전투 통합
  경계에 남아 있다.
- 3단계: 시작 전. 자동 함수 경계와 후보 주소가 있으며 메커니즘 역할은 아직 `추정`이다.
- 4단계: 부분 진행. K01 영웅의 공격 상태 진입 이후 phase·효과 시점·회복은 완료했지만 대상
  검색·사거리·사망 정리와 원본 좌표·시간 변환은 미확정이다.

## K01 MVP 완료 조건

다음 항목이 모두 충족돼야 단기 목표를 완료로 판정한다.

1. K0110 브리핑에서 K0115 미션 시작, K0120 봉화대·증원 이벤트와 승리·패배 결과까지 한 세션으로
   진행된다.
2. K01 맵 크기·지형·초기 엔티티·소유자·핵심 위치가 원본 맵 데이터와 연결된다.
3. K01에 보이는 주요 인물·유닛·건물의 이름과 자원이 원본 타입·SPR에 맞고, 플레이 중 사용되는
   방향·상태 프레임에 정적 근거가 있다.
4. 이동·충돌·경로, 공격·피해·사망, 건설과 봉화대 완성 중 K01 결과에 영향을 주는 규칙을 독립
   테스트 벡터로 재현한다.
5. 브리핑·미션 대화, 핵심 HUD·선택·목표 표시, 음성·음악과 결과 화면이 확인된 원본 자원·배치·
   타이밍을 사용한다.
6. 영웅 손실, 봉화대 조건 미충족·충족, K0120 일회성 실행, 승리·패배 지연의 경계 테스트가 있다.
7. 미확정 값은 원작 일치로 표시하지 않으며, K01의 핵심 흐름에 남은 임시 대체물은 완료 목록에
   구체적으로 드러난다.

통과 조건:

- 모든 기존 분석 산출물에 `유지`, `재검증`, `보관` 중 하나의 상태가 부여된다.

## 1단계: 정적 분석 파이프라인

- Ghidra 기반 프로젝트를 동일한 설정으로 반복 생성할 수 있게 한다.

- 분석 입력과 산출물에 원본 실행 파일 해시를 포함한다.
- 수동으로 만든 간이 x86 디코더를 의미 복원의 기반으로 사용하지 않는다.

통과 조건:

- 깨끗한 환경에서 같은 함수·참조 목록을 재생성할 수 있다.
- 분석 산출물에서 원본 주소와 바이트 범위를 역추적할 수 있다.

통과 조건:

- 동일 오프셋을 서로 다른 구조체의 필드로 혼동하지 않는다.

### 2A: 스프라이트 매핑 복구 파일럿

사용자에게 직접 드러난 오매핑을 우선 차단하기 위해 다음 세 질문을 병행하지 않고 순서대로 푼다.

0. 전체 타입 정체 카탈로그 — 완료: 클래스 1~95의 원본 이름·슬롯·기본 프레임·flags·SPR 경로
1. 유닛 한 종류의 엔티티 종류·행동·방향→프레임 식 — 부분 완료: 내부 클래스 2는
   `조선 창병`·슬롯 100으로 식별, 상태 1·2 이동 의미와 방향식 완료, 상태 1 일반 이동 이식;
   상태 2 통합·특수 분기 base·idle·전투는 미확정
   - K01 영웅 확장: 클래스 76 `조선 권율`과 78 `조선 유성룡`의 전용 SPR·상태 8 idle·
     1 일반 이동·4 공격·7 사망 이식 완료; 공격 효과 phase 7은 정적 확정, 초 단위 재생 속도·
     피격·사망 표시 수명은 미확정
2. 건물의 건설·정상·피해→본체·오버레이 프레임 식 — 본체 2개 완료: 조선 본영과 조선 봉화대
   frame 0~7·정상 7·반파 8; 각 자원의 나머지 프레임과 오버레이는 미확정
3. `SPEECH` 초상화 ID→자원·프레임 식 — 완료: `hero.spr`의 17개 ID 표

별도 UI 파일럿으로 `SPEECH` 숫자 슬롯 0~3의 초상화 사각형과 대사 좌표도 정적 확정·이식했다.
제목·목표·버튼과 전체 HUD 레이아웃은 이 완료 범위에 포함하지 않는다.

통과 조건:

- 자원 경로, 상태 값, 방향·체력·ID 값과 최종 프레임이 하나의 정적 데이터 흐름으로 연결된다.
- 기본 분기, 범위 밖 입력과 미러링을 포함한 테스트 벡터가 있다.
- 감사 보고서에서 증명한 항목만 `정적 확정`으로 승격한다.
- 확정된 벡터를 적용하기 전에는 현행 프레임 번호를 손으로 보정하지 않는다.

## 3단계: K01 미션 메커니즘

- K0110·K0115·K0120 호출 흐름
- 봉화대 검색과 완성 조건
- 원샷 플래그와 후속 효과
- 보호 영웅 생존 조건
- 승리·패배 타이머와 결과 전환

통과 조건:

- 관련 함수의 전체 분기와 데이터 흐름을 설명할 수 있다.
- 합성 엔티티 입력으로 스크립트 호출과 승패 결과를 재현한다.
- 원본에 없는 추정값이 테스트 기대값에 포함되지 않는다.

이 단계 통과는 K01 MVP 전체 완료가 아니다. 이후 공격 주기, 적합성 테스트, 검증 단위 이식과
K01 종단 검증까지 통과해야 한다.

## 4단계: 공격 주기 파일럿

유닛 한 종류에 대해 대상 선택부터 다음 행동까지 복원한다.

1. 대상 검색과 유효성 판정
2. 이동과 사거리 판정
3. 공격 상태 진입
4. 타격 프레임과 피해 시점
5. 공격력·방어력·속성 계산
6. 투사체 또는 즉시 피해
7. 사망과 대상 참조 정리
8. 재사용 대기와 다음 상태

현재 K01 영웅 제한 범위에서는 3·4·6·8의 일부를 완료했다. 권율은 8-phase 중 phase 7에서
직접 피해 kind 1, 유성룡은 10-phase 중 phase 7에서 subtype `0x0c` 투사체를 생성한다.
두 영웅 모두 phase가 0으로 돌아오면 주 회복 카운터를 초기화하고 짝수 전역 틱 두 번 뒤 다시
준비된다. 권율의 기본 payload 80과 직접 피해 수식에 이어 유성룡의 subtype `0x0c`는 보수적인
좌표 accepted subset `0..32767`에서 경로·도착·effect kind `9` 피해를 재현했다. 원본 caller
전체 signed-WORD 좌표 범위는 미확정이다. 자세한 생성 phase는
[K01 영웅 일반 공격 파일럿](reverse-engineering/mechanics/k01-hero-basic-attack-pilot.md),
후속 수명과 피해는
[K01 유성룡 투사체 파일럿](reverse-engineering/mechanics/k01-ryu-projectile-pilot.md)을 따른다.

통과 조건:

- 경계 사거리, 최소 피해, 대상 소멸과 공격 취소를 포함한 테스트 벡터가 있다.
- 화면 관찰 없이 상태 전이와 결과를 재현한다.

## 5단계: 적합성 테스트

- 원본 주소와 입력 상태가 포함된 테스트 벡터 형식을 만든다.
- 반환값뿐 아니라 메모리 변경, 후속 호출과 이벤트 순서를 검사한다.
- 격리 실행이 가능한 원본 함수는 에뮬레이션을 우선 검토한다.
- 현재 구현의 문자열이나 함수 존재 여부를 원작 검증으로 사용하지 않는다.

통과 조건:

- 원본 분석 결과와 포팅 구현을 동일한 입력으로 비교할 수 있다.

## 6단계: 검증된 단위 이식

- 검증된 메커니즘과 현재 구현의 차이를 먼저 기록한다.
- 임시 보정이 아니라 해당 도메인 계층에서 기존 구현을 교체한다.
- 분석 문서와 테스트 벡터를 구현 테스트에 연결한다.
- 불필요해진 추정 상수와 fallback을 제거한다.

통과 조건:

- 해당 메커니즘이 `원본 기반`으로 표시되고 회귀 테스트가 통과한다.

## 7단계: K01 종단 완결과 이후 범위 확장

먼저 K01 MVP 완료 조건을 종단 시나리오로 검증한다. K01이 완료된 뒤에만 다음 순서로 일반화한다.

다음 순서로 진행한다.

1. 데이터 포맷과 엔티티 정의
2. 자원·생산·건설·연구
3. 이동·충돌·경로 탐색
4. 공격·투사체·피해·사망
5. 명령 큐와 상태 머신
6. 캠페인
7. AI
8. 애니메이션
9. 카메라·선택·입력
10. HUD와 메뉴
11. 음향과 연출
12. K02 캠페인

## 8단계: 제한적인 동적 검증

동적 분석은 [동적 검증 예외 지침](agent-guides/dynamic-validation.md)의 조건을 모두 만족할 때만 수행한다.
게임 플레이 재현은 하지 않고, 저장 상태와 사전 설치한 브레이크포인트로 질문 하나만 확인한다.

동적 검증은 각 단계의 기본 통과 조건이 아니다.

## 재평가 지점

- K01 파일럿 완료 후 정적 분석 방법의 재현성과 비용을 평가한다.
- 공격 주기 파일럿 완료 후 실시간 상태 머신까지 같은 방법을 확장할지 평가한다.
- 파일럿이 실패하면 VM 플레이 방식으로 돌아가지 않고 정적 분석 도구·함수 경계·자료구조 가정을 먼저
  재검토한다.
