# 원본과 포팅 구현의 경계

## 목적

원본 게임에서 확인한 사실과 이 프로젝트가 별도로 선택한 설계를 섞지 않기 위한 경계 문서다.

## 정보 흐름

```text
원본 바이너리·데이터
  -> 정적 분석 산출물
  -> 명시적인 메커니즘 명세와 테스트 벡터
  -> 독립 참조 구현 또는 격리 재현
  -> 웹 포팅 구현
```

웹 포팅 구현을 원본 동작의 근거로 역참조하지 않는다.

## 원본 사실

다음은 원본 분석으로만 확정한다.

- 수치와 수식
- 분기 조건과 상태 전이
- 자료구조 필드와 테이블
- 타이머와 이벤트 순서
- 캠페인 트리거와 승패 조건
- 애니메이션 프레임 선택 규칙
- UI 좌표계, 그리기 순서와 입력 영역

## 프로젝트 설계

다음은 원본과 달라도 되는 프로젝트 선택이지만, 차이를 문서화해야 한다.

- 브라우저와 Phaser에 맞춘 렌더링 구조
- 반응형 화면 대응
- 저장 형식과 개발자 도구
- 접근성 기능
- 원본 네트워크를 재현하지 않는 싱글플레이 구조
- 원작 분석이 끝나기 전의 임시 프로토타입

## 구현 표기

원작 관련 구현은 다음 중 하나로 표시한다.

- `원본 기반`: 확정된 원본 분석과 재현 테스트에 기반
- `프로토타입`: 원본 분석 전의 임시 구현
- `부분 이식`: 정적 확정된 규칙 일부만 반영
- `의도적 적응`: 원본 규칙을 알고 의도적으로 변경한 웹 적응
- `프로젝트 전용`: 원작에 대응 항목이 없는 프로젝트 기능

`원본 기반`은 [증거 기준](../reverse-engineering/evidence-levels.md)의 정적 확정과 재현 완료를 모두
만족해야 한다.
