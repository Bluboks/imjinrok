# 문서 작성 규칙

## 단일 출처

- 같은 사실을 여러 문서에 복사하지 않는다.
- 프로젝트 전체 상태는 `docs/project-status.md`에 기록한다.
- 메커니즘 분석 상태는 `docs/reverse-engineering/status-matrix.md`에 기록한다.
- 함수 주소와 역할은 `docs/reverse-engineering/function-map.md`에 기록한다.
- 메커니즘의 상세 근거는 해당 `mechanics/` 문서 한 곳에 기록한다.

다른 문서에서는 원문을 링크하고 짧게 요약한다.

## 사실과 계획의 분리

- 확인된 원본 사실과 앞으로 할 작업을 같은 목록에서 섞지 않는다.
- 계획 문서에는 통과 조건을 포함한다.
- 완료되지 않은 작업에 `완료`, `달성`, `검증됨`을 사용하지 않는다.
- 현재 구현의 존재와 원작 일치 여부를 별도 열로 기록한다.

## 증거 표기

원작 관련 주장은 [증거 기준](../reverse-engineering/evidence-levels.md)을 따른다. 최소한 다음을 기록한다.

- 원본 파일과 SHA-256
- 함수 또는 데이터의 가상 주소
- 분석한 바이트 범위
- 제어 흐름과 데이터 흐름
- 관련 구조체 필드와 상수
- 해석 상태와 남은 불확실성
- 재현 테스트 또는 미재현 사유

## 생성 자료

- 도구가 생성하는 표를 손으로 복사해 여러 문서에 유지하지 않는다.
- 생성 산출물에는 생성 명령과 입력 해시를 포함한다.
- 생성 결과와 사람이 작성한 해석을 구분한다.
- 문자열이나 바이트 존재 검사를 의미 검증으로 표현하지 않는다.

## 보관

- 오래된 문서는 삭제하지 않고 날짜가 붙은 `docs/archive/legacy-YYYY-MM-DD/`로 이동할 수 있다.
- 보관 문서 첫머리에 현행 문서가 아니라는 안내를 둔다.
- 보관 문서에서 사실을 가져올 때는 현행 방법론으로 재검증한다.
- 보관 문서 링크는 역사적 출처로만 사용한다.

## 언어와 명명

- 설명 문서는 한국어를 기본으로 한다.
- 원본 문자열, 함수 식별자, 명령어와 파일명은 원문을 유지한다.
- 주소는 `0x00400000`처럼 자릿수를 유지한다.
- `parity`는 모호하게 사용하지 않고 `원작 일치`, `정적 확정`, `재현 완료` 중 정확한 상태를 쓴다.
